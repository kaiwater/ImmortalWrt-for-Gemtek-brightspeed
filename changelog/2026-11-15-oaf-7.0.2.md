# 2026-11-15 OAF 从 feed 旧版换成 7.0.2

## 问题

`naoki66-base` 之前用的是 `immortalwrt/packages` feed 里的 `open-app-filter`：

```
appfilter 2026.04.20~569f93bf   （对应 LuCI 侧 luci-app-appfilter 6.1.4）
```

而 `kaiwater/wrt_release` 用的是 `kenzok8/small-package` 里的
**appfilter 7.0.2 + luci-app-oaf 7.0**，差一个大版本。

## 处理

按 wrt_release 的方式（sparse 取 small-package 的三个包目录），把这部分 vendor 进本仓库：

```
package/oaf/oaf/               → kmod-oaf（内核模块 oaf.ko）
package/oaf/open-app-filter/   → appfilter 7.0.2（oafd 用户态）
package/oaf/luci-app-oaf/      → luci-app-oaf 7.0-r2（LuCI 界面）
```

同步基准：

```
repo    https://github.com/kenzok8/small-package
commit  41ae244f30603368d739786f496e00700f55464f（2026-11-15）
```

`custom/config.fragment` 改用：

```
CONFIG_PACKAGE_luci-app-oaf=y
CONFIG_PACKAGE_luci-i18n-oaf-zh-cn=y
CONFIG_PACKAGE_appfilter=y
CONFIG_PACKAGE_kmod-oaf=y
```

不再选择 `luci-app-appfilter` / `luci-i18n-appfilter-zh-cn`。

## 与上游的差异（都在 package/oaf/README.md 里）

1. **ACL 文件改名**：`appfilter` 与 `luci-app-oaf` 都装
   `/usr/share/rpcd/acl.d/luci-app-oaf.json`，apk 不允许两包覆盖同一路径
   （wrt_release 的 `fix_appfilter_acl_conflict` 处理的是同一件事）。
   把 appfilter 的那份装成 `acl.d/appfilter-oaf.json`。
2. 删除上游误提交的 `luci-app-oaf/luasrc/view/oaf/.dashboard.htm.swp`。
3. 加 `PKG_PO_VERSION:=7.0.2`，否则翻译包版本会变成 `0`。

## feed 去重

`immortalwrt/packages` 里仍有一份 `open-app-filter`，会定义同名
`appfilter` / `kmod-oaf`。CI 增加了一步：

```
Drop duplicate open-app-filter from feeds
  rm -rf package/feeds/*/open-app-filter
```

本地构建同样要删一次（`package/feeds/packages/open-app-filter`），否则
metadata 扫描会看到两个同名包。
