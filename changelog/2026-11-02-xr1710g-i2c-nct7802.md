# XR1710G 恢复 NCT7802 主板温度与风扇控制

| 项 | 值 |
| --- | --- |
| 日期 | 2026-11-02 |
| 分支 | `naoki66-base` |
| 提交 | `ef168521c4`（首个包含本修复的镜像为 `20261102-87a4119c`） |
| 变更文件 | `target/linux/airoha/dts/an7581-xr1710g.dts` |
| 类型 | 设备树修正（删除 1 行 compatible 覆盖） |
| 适用设备 | Gemtek XR1710G（`gemtek_xr1710g`，0x700000 原厂 U-Boot 布局） |
| 状态 | 已实机验证 |

---

## 1. 背景

从旧固件切换到 naoki66 基线后，LuCI「风扇控制」页面出现：

- **主板（风扇曲线）温度恒为 0°C**
- 风扇 PWM / 转速无读数
- 但其它传感器全部正常：CPU 51°C、10G 芯片 43°C、交换机芯片 67°C、
  2.4 GHz 45°C、5 GHz 39°C、6 GHz 39°C

说明问题只出在 NCT7802 这一颗芯片上，而不是整体传感器框架。

## 2. 根因

`an7581-xr1710g.dts` 的 `&i2c0` 覆盖了从 `an7581.dtsi` 继承的 compatible：

```dts
&i2c0 {
	compatible = "airoha,airoha-i2c";   /* 问题所在 */
	clock-frequency = <400000>;
	status = "okay";
	hwmon@2e { compatible = "nuvoton,nct7802"; reg = <0x2e>; };
};
```

`airoha,airoha-i2c` 属于树外的 `kmod-airoha-i2c` 驱动，而该驱动已经在
`993e4778fc ("del kmod-airoha-i2c")` 中被删除（同时从 `1710.config` 和
`an7581.mk` 的 DEVICE_PACKAGES 移除），**但设备树里的 compatible 覆盖没有跟着清理**。

当前 airoha 内核配置里只剩 `CONFIG_I2C_MT7621`，它的 `of_match` 表只认
`mediatek,mt7621-i2c` / `ralink,mt7621-i2c`，因此：

1. `i2c0` 控制器不 probe，`/sys/bus/i2c/devices/` 为空
2. 挂在 `0x2e` 的 `nct7802` 不枚举，`hwmon` 列表里没有它
3. 板温、风扇曲线、PWM、转速全部消失

这也解释了一个容易误判的现象：**从 2010 引入的 compatible 写进了 1710 的 DTS，
但 2010 自己把 PON 光模块 en7572 放在 i2c0（没有覆盖），所以 2010 的 PON 一直正常。**

## 3. 变更内容

删除 `an7581-xr1710g.dts` 中 `&i2c0` 的 compatible 覆盖，保留基础
`mediatek,mt7621-i2c`，并加注释说明原因。

范围限制：

- 只改 `an7581-xr1710g.dts`（0x700000 布局）
- `an7581-gemtek-xr1710g-ubi.dts` 本来就没有该覆盖，不动
- XG2010G 的两个 DTS 完全不动（其 i2c1 上虽有同样的遗留，但无设备，且不属于本修复范围）

## 4. 验证方式

实机：Gemtek XR1710G，`sysupgrade` 保留配置升级到
`immortalwrt 20261102-87a4119c-2248ed75`。

```text
$ i2cdetect -l
i2c-0   i2c   1fbf8000.i2c0   I2C adapter

$ i2cdetect -y 0
20: -- -- -- -- -- -- -- -- -- -- -- -- -- -- UU --

$ for h in /sys/class/hwmon/hwmon*; do echo "$(basename $h): $(cat $h/name)"; done
hwmon0: mt7530_0:05
hwmon1: mt7530_0:08
hwmon2: nct7802
hwmon3: mt7996_phy0.0
hwmon4: mt7996_phy0.1
hwmon5: mt7996_phy0.2

$ dmesg | grep i2c-mt7621
[    3.856779] i2c-mt7621 1fbf8000.i2c0: clock 400 kHz
```

LuCI 数据源（`ubus call luci.fan getStatus`）：

```json
{
	"temp_board": 41,
	"fan_rpm": 2269,
	"fan_pwm": 145,
	"fan_percentage": 56,
	"fan_mode": 2,
	"fan_mode_desc": "Automatic"
}
```

sysfs 原始值：

```text
temp1_input = 41500      # 主板 41.5°C
fan1_input  = 2269       # RPM
pwm1        = 145        # 约 57%
pwm1_enable = 2          # 自动曲线
```

**已验证**：i2c0 枚举、nct7802 绑定、板温、转速、PWM 自动模式、400 kHz 时钟。

**未验证**：

- XG2010G（无硬件）
- 风扇在不同温度下的曲线响应（只确认了自动模式与当前档位）
- `temp2_input`（远端二极管，悬空时读数 127°C，属正常，与本修复无关）

## 5. 影响范围

- 仅 `gemtek_xr1710g`（0x700000 布局）
- 恢复主板温度显示、风扇自动曲线、手动 PWM、转速读数
- 不影响 CPU/10G/交换机/无线传感器（它们走各自 hwmon）
- 不影响 XG2010G、`gemtek_xr1710g-ubi`

## 6. 如何确认生效

```sh
ls /sys/bus/i2c/devices/            # 应看到 i2c-0 与 0-002e
grep -l nct7802 /sys/class/hwmon/hwmon*/name
cat /sys/class/hwmon/hwmon2/temp1_input   # 40~60°C 量级（毫摄氏度）
cat /sys/class/hwmon/hwmon2/fan1_input    # RPM
cat /sys/class/hwmon/hwmon2/pwm1_enable   # 2 = 自动
```

LuCI → 状态 → 风扇控制，主板温度不再是 0°C。

## 7. 风险与回滚

- 风险：如果某块板子的 i2c0 上真的需要 `kmod-airoha-i2c` 的专用实现，
  回退到 mt7621 驱动可能不兼容。本板实测 400 kHz 与 NCT7802 读写正常。
- 风险：`kmod-airoha-i2c` 已被上游删除，不存在“驱动仍在使用”的隐式依赖。
- 回滚：恢复该行 compatible 覆盖即可，但同时必须让 `kmod-airoha-i2c` 重新
  进入构建，否则会退回到“没有 i2c 适配器”的状态。
