# Changelog 目录

本目录存放**单次变更的详细报告**。根目录的 [`CHANGELOG.md`](../CHANGELOG.md) 只保留
摘要条目，一句话说清“改了什么”，细节都落到这里。

## 约定

- 文件名：`YYYY-MM-DD-<短描述>.md`；同一天有多次变更时在末尾加序号（`-2`、`-3`）。
- 语言与根 `CHANGELOG.md` 保持一致：中文正文，代码/命令/字段名保留原文。
- 每篇报告固定包含以下部分，缺项写“不适用”而不是省略：
  1. 背景（为什么要做）
  2. 根因（如果是在修问题）
  3. 变更内容
  4. 验证方式（做了什么验证、结果如何、**哪些还没验证**）
  5. 影响范围（哪些设备、哪些频段、哪些配置会受影响）
  6. 如何确认生效
  7. 风险与回滚
  8. 参考
- 记录范围：会影响本仓库构建产物或设备运行行为的变更。纯上游 ImmortalWrt 合并
  仍然只写在 `CHANGELOG.md` 里，不单独开报告。
- 报告一旦提交就不改写结论；后续有新进展时追加「后续」一节，保留原始判断。
